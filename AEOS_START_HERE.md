# AEOS v0.2 — Drop-in Project Root

**Purpose:** Drop the operational files into the root of any new software project. No Python installer or copied template files are necessary. The coding agent initializes `PROJECT.md` and `STATE.md` itself **after brainstorming** and **when asked to initialize**.

## Put these at the project root

```
New Project/
  AGENTS.md              ← generic bootstrap / Codex
  CLAUDE.md              ← Claude Code bootstrap
  GEMINI.md              ← Gemini adapter (optional)
  AEOS_START_HERE.md     ← human usage note
  aeos/                  ← operating procedures and templates
  docs/                  ← product specs, if available; agent may create later
  PROJECT.md             ← generated by the agent during AEOS INIT
  STATE.md               ← generated by the agent during AEOS INIT
  [source files...]       ← only after explicit BUILD
```

Do **not** copy this ZIP's outer folder into the repo and assume it will be discovered. Extract the *contents of `AEOS_v0_2_Drop_In`* into the repo root so `AGENTS.md`, `CLAUDE.md`, and `aeos/` are immediately visible. Do not overwrite any existing instruction files; reconcile conflicting rules first.

## Two commands, two distinct permissions

- `AEOS INIT` — authorized documentation/scaffolding phase after requirements are clear. Agent reads available idea/spec, verifies existing work, creates/updates `PROJECT.md` and `STATE.md` and only justified planning docs, proposes first milestone. **No app code, migrations or deployment.**
- `BUILD M1` — separately authorized implementation of milestone M1, after any project-specific gates are satisfied. Agent implements, verifies, updates records, and stops before a Git commit.

No direct command parser is installed; these are natural-language instructions interpreted by the coding agent. `AEOS INIT` is not automatic merely because files exist.

## First message to Claude Code / Codex / Gemini

> Read AGENTS.md and the AEOS bootstrap procedures. The product has been brainstormed, and the attached/supplied project material is the requirements source. AEOS INIT: inspect the current directory and existing documents, preserve everything already present, initialize only the essential project records, identify open decisions and propose the first bounded milestone. Do not implement application code, commit, push or deploy. Stop for review.

## Existing project or integration

Ask for `RECOVER` to audit the repo and relevant adjacent codebases **read-only** before initialization, and use `AEOS INIT` to write only project-specific indexing/state once authorized. Do not copy or rewrite existing product blueprints.

## Human approval boundaries

High autonomy **inside** a bounded BUILD; human-reviewed local Git commits; no hidden push/deploy; ask before materially changing requirements/architecture/security or performing consequential outside-world actions.
