**Owner:** Project commissioner / authorized lead

## What this package is

A repository-ready Markdown blueprint for **YCT Alert**, an independent campus incident-reporting application serving the Yaba College of Technology community, with a public web interface, a Capacitor Android application, and a separate administrative dashboard. Its limited integration with **YCT Map** gives Alert optional campus place references and lets Map show approved, safe incident markers.

This ZIP contains **planning documents and work instructions, not implementation code**. It is intended to let the build begin in measured, reviewable stages after the relevant decision gates. No document authorizes deployment, production data changes, or institutional claims.

## Five architectural invariants

1. **Map owns geography and navigation; Alert owns incident reports, incidents, and administrators.** No shared DB, auth session or direct writes across products.
2. **Public incident submissions require no account.** Administrative actions require authenticated, server-authorized accounts.
3. **Only authorized administrators can approve public incidents.** Report volume never automatically activates an incident.
4. **No false response claims.** `report received` is not `reviewed`, `approved`, or `help dispatched`.
5. **Both products survive the other's outage.** Browser reporting remains available without an installed APK, and manual location works without Map.

## Proposed V1 shape

- `apps/public`: single Vite/TypeScript frontend build, served as a website and bundled within Capacitor Android. UI framework is a **provisional** choice; proposed default React for early planning.
- `apps/admin`: separate desktop/mobile-responsive admin web app.
- `services/api`: dedicated TypeScript HTTP API (suggested Fastify), separate PostgreSQL database, migrations, incident-matching service and RBAC. This stack is an **engineering recommendation**, not a user-approved decision.
- `packages/contracts`: versioned schema/OpenAPI definitions that all consumers follow.
- `android`: Capacitor project generated by the proper tooling, not hand-crafted by AI.

Do not create code until Gate G0 from `14_BUILD_ROADMAP.md` and `18_OPEN_QUESTIONS.md` is approved. A prototype can use **clearly labelled synthetic incident data only**.

## Quick launch checklist for a new agent

- Read root `AGENTS.md` and the external `YCT_ALERT_AGENT_START_HERE.md` supplied next to the ZIP.
- Read the ten most relevant documents for the assigned task, not just `README.md`.
- Identify dependencies and write a change plan before editing.
- Do not embed, repeat or log any real passwords. The reserved super-admin **username** is documented; the password is purposely omitted.
- Do not use production databases, run seed/reset scripts, commit, deploy, or change YCT Map without owner approval.
- On completion, supply a structured evidence report: files changed, tests actually run, pass/fail/blocked, visual/device verification, security impact, risks and unresolved decisions.
